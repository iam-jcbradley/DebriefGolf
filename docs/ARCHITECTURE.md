# Architecture

## Stack

| Layer | Choice | Notes |
|---|---|---|
| Frontend | Next.js 15 (App Router, TypeScript) | `apps/web`, pnpm-managed |
| UI | Tailwind CSS v4 + shadcn/ui | components installed on demand via `pnpm dlx shadcn@latest add <component>` |
| Charts | Recharts | round/practice diagnostics |
| Maps | Mapbox GL + deck.gl | hole satellite imagery, dispersion overlays (Phase 4) |
| Client cache | IndexedDB | offline-friendly audit wizard draft state (Phase 3) |
| Backend | FastAPI (Python 3.12+) | `apps/api`, uv-managed |
| ORM | SQLModel / SQLAlchemy + GeoAlchemy2 | table models + typed queries; GeoAlchemy2 gives SQLAlchemy native PostGIS `Geometry` column types |
| Migrations | Alembic | `apps/api/alembic/`, autogenerate from `SQLModel.metadata` |
| Data processing | NumPy, Pandas | Strokes Gained math, IQR outlier rejection |
| .FIT parsing | fitparse | Garmin activity file ingestion |
| Database | PostgreSQL 16 + PostGIS | spatial types for hole geometry, shot coordinates |
| Backend tests | pytest + httpx `TestClient` | |
| Frontend tests | Vitest + React Testing Library | |

## Repo layout

```
DebriefGolf/
├── docs/                  # PRD, this file, development plan, data privacy
├── infra/db/init.sql      # enables the postgis extension on first boot
├── docker-compose.yml     # db + api + web for local dev
├── Makefile                # make up / dev-web / dev-api / test / lint
├── apps/
│   ├── web/                # Next.js 15 app
│   │   └── src/app, src/components, src/lib
│   └── api/                 # FastAPI app
│       ├── app/{core,db,models,api/routes,services}, tests/
│       ├── app/db/seed.py   # demo round data — `make seed`
│       └── alembic/         # migrations, autogenerated from SQLModel.metadata
└── .github/workflows/ci.yml
```

`apps/web` and `apps/api` are independent projects (no Turborepo/Nx) — each has its own lockfile and is built/tested on its own. They're tied together only through `docker-compose.yml` for local dev and the CI workflow's two parallel jobs.

## Data flow

1. **Ingestion** — a round enters the system either via the Garmin Connect OAuth 2.0 webhook, a manual `.FIT` upload (fallback when the webhook fails), or an R10/R50 CSV/JSON export. All three land in `app/services/parsers/`.
2. **Persistence** — parsed shots/rounds are written as SQLModel records into Postgres; spatial fields (shot coordinates, green boundary polygons) use PostGIS geometry types so radius/containment queries (e.g. "was this putt outside the green?") run in the DB rather than in application code.
3. **Analytics** — `app/services/` computes Strokes Gained, Tiger 5 violations, Clean Card Index, and Smart Bag club stats from persisted shots, benchmarked against the Broadie SG lookup tables.
4. **API** — FastAPI exposes round-level and bag-level analytics as JSON to the frontend.
5. **Presentation** — Next.js renders the Round Snapshot / Tiger 5 meter / hole replay / practice hub views described in PRD §8, with Mapbox/deck.gl handling the spatial overlays and Recharts handling trend charts.

## Decisions log

- **Plain `apps/` folders over Turborepo/Nx.** The monorepo spans two languages (TS + Python), so a JS-focused orchestration tool buys little; docker-compose and a root `Makefile` are enough to run both sides together.
- **pnpm (frontend) + uv (backend).** Both are fast, disk-efficient, and have become the modern default for their ecosystems; `uv` in particular collapses what would otherwise be a separate venv + pip + pip-tools setup into one tool and one lockfile (`uv.lock`).
- **Runnable skeleton, not just folders, for the bootstrap.** Both apps boot via `docker compose up` and the API's `/api/health` endpoint answers, so the repo is provably working before any feature code (Phase 1+) is written. (Phase 12 split this into `/api/health` — liveness, no DB dependency — and `/api/ready`, which is the one that actually proves DB connectivity; a real health probe should point at `/ready`.)
- **`postgis/postgis:16-3.4` image over installing PostGIS manually.** The PRD calls for spatial queries (green boundary containment, shot dispersion) from day one; the official image ships the extension pre-built.
- **Alembic autogenerate whitelists our own tables (`include_object` in `alembic/env.py`).** The `postgis/postgis` image also installs `postgis_tiger_geocoder`/`postgis_topology`, which otherwise show up as "tables to drop" during autogenerate.
- **GeoAlchemy2's auto-created GIST spatial indexes are left out of migrations' explicit `create_index` calls.** GeoAlchemy2 creates the index itself at table-creation time (`spatial_index=True` default); an explicit `op.create_index` for the same index in the generated migration causes a duplicate-index error, so those lines are removed by hand after autogenerate.
- **Docker builds pin the exact pnpm version (`packageManager` in `apps/web/package.json` + `corepack install`) instead of `corepack enable` alone.** Without pinning, `corepack enable` fetches whatever pnpm is newest at build time; a version drift between host (pnpm 10.x) and a freshly-resolved container (pnpm 11.x) surfaced as a hard install failure (pnpm 11 defaults to rejecting packages published in the last 24h as a supply-chain guard). Pinning keeps local and containerized installs identical.
